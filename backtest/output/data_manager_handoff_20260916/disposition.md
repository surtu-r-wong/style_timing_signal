## 3. 核心裁定：WSS 指数资金流**不能**写进 `index_money_flow`

请求函 §3.1 把这个问题交给受理方。**裁定：不能共用，必须另立一张表。**
不是保守，是有三条硬证据：

### ① 接口层面它们就不是一回事

网关 `market_money_flow` 的 WSET 参数是：

```
wset_options: "startdate={start};enddate={end};frequency=day;sector={sector};securitytype=A股"
```

**参数是 `sector=`，取的是板块聚合**，`000300.SH` 只是这个板块挂的一个代表代码
（所以 `wind_sector` 才会 NOT NULL）。而 WSS 的 `mfd_inflow_m` 打在指数代码上，
取的是**该指数成分股的资金流聚合**。两者是不同的统计总体，不是同一序列的两种单位。

### ② 请求函自己的实测已经证否了「只是单位差」

§9.3：创业板全板 WSET 与 `399102.SZ` 指数 WSS、科创全板 WSET 与 `000680.SH` 指数 WSS，
**换算 10,000 倍后仍有差异，尾盘甚至异号**。异号不可能是单位问题。

### ③ 共用会**静默破坏已冻结的回测**

主键是 `(index_code, trade_date)`，`src` 不在键里。已有冻结回测按
`index_code` 直接读、**不过滤 `src`**。一旦把 WSS 的 `000300.SH` 写进去：
- 用 upsert → **覆盖** WSET 历史，冻结回测的输入被改；
- 把 `src` 加进主键 → 同一个 `(index_code, trade_date)` 变成两行，
  不过滤的查询**静默返回两倍行数**。

两条路都是「改了别人已经冻结的东西而没人会发现」。**不接受。**

### 我考虑过但否掉的替代方案

**「只放 500/1000，不碰 300」** —— 今天不撞，但一张表里一半是板块口径、
一半是指数口径，`wind_sector` 这列对新行无意义。更要命的是：
**提出方的研究正是要横向比较 300/创业板 与 500/1000**（§2「不再始终借用 300/创业板」）。
若 300 是 WSET 板块、500 是 WSS 指数，这个比较从第一天就被口径差污染 ——
而这正是 §9.3 已经实测到的差异。**这个方案表面省事，实际上让研究结论不可信。**

### 裁定的实际含义

- **P0 照旧走 WSET，写进现表**，不动既有 7,403 行，不改口径；
- **P1 走新表**，并且 300/创业板/科创**也应在新表里补一份 WSS 口径**，
  这样提出方的横向比较才是同源的；
- 两张表并存，各自 `src` 单一，谁都不覆盖谁。
