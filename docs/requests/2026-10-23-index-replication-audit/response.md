## 调样修正的实现边界

离线对照把普通持有期改为 `[实施日, 下一实施日)`，末期仍含运行器指定的终止日。通过现有 `(start,end]` 查询时，人工实验使用“实施日前一自然日、下一实施日前一自然日”作查询边界；只移动查询边界，不平移已算好的收益标签。周末和假期不需要猜测交易日。

尚不能直接全局改 `_daily_returns`：`axis_rotation_builder` 同时用它读取截止日内的因子历史和向前收益；改变默认闭区间会影响历史因子。`build_tail_pair`、`build_geometric_pairs` 也复用 `_leg_returns`，各运行器最后一项是含当日的观察终点，而不是下一调样日。后续应在构建调用层明确区分实施日与终止日，并保持这些路径一致。

另一个约束是 `build_pair(official_space=False)` 仍按实施日取样本和财务数据；若把该路径无条件提前到实施日开盘持有，会产生当日信息可得性问题。官方化路径使用 `review_cutoff`，两种时间语义不能在修边界时混改。

当前得分权重也未证明等于实施日前收盘权重。新 run 的边界对照只固定原输入权重演示收益归属，不能取代权重因子参考日、股份变更及除数维护核验。因此本轮保留现有计算代码与正式历史 run，真实数据齐备后单独修正、同窗比较、登记新证据。
