# 前瞻账户核算实施计划

范围依据：[实施补充](../requests/2026-10-14-multi-asset-operational-returns/forward-account-implementation.md)。仅实现本地软件与合成验收，保留已接受的 response.md，不部署、不初始化真实账户、不调用行情供应商。

## 交付与边界

- 新增 `operational_returns/`：读取原生登记、显式账户配置校验、信号观测快照、SQLite 增量账本与 ReturnFeed 导出命令。
- 初版支持单账户单标的、单币种 paper 核算，现金证券和线性逐日盯市合约。明确单位/乘数、名义杠杆、费用、现金利息、融资、借券、保证金、手数与模拟执行规则。多账户分别核算后导出独立系列，不合成组合。
- 不支持真实成交接入、外部申赎、多币种、期权、自动换月、分红拆股等公司行动；遇到这些输入明确拒绝，不静默忽略。缺少真实参数的账户不初始化。
- 读取 `SIGNALS` / `PRODUCTION_MAPPING` / `REFERENCE_OUTPUTS` / `POOLS`，只初始化显式配置的账户。映射与账户配置固定在身份中，登记增删在下次校验中生效。
- 完整覆盖的显式日历决定应有估值日；只接受前一会话已观测且在执行前可用的信号。初始化后先建立现金基准，首个完整估值区间才产生收益。
- SQLite 事务保存配置、现金/持仓、输入摘要与不可变修订；重复输入幂等、不同输入显式修订最近区间。失败保留上次成功状态并写独立尝试状态。
- 导出完整已积累前瞻窗口，真实生成时间；内容未变保留旧文件时间；版本文件不可覆盖、latest 原子替换。合成状态不能导出到正式路径。

## 实施顺序与验收

1. 先写公共行为测试：两个连续区间、一次换仓计费、独立现金/NAV/PnL算式、重复运行。
2. 实现严格配置、完整日历、初始化/基准、核算事务；补齐空头、杠杆、融资与线性合约结算测试。
3. 实现原生 CSV 观测快照、CLI、导出；测试迟到/缺日/缺行情/配置漂移/故障恢复/显式修订/Schema。
4. 提交待填参数模板与明确标识的合成输入，可复现 CLI 示例只写临时目录。
5. 新增 implementation-response.md，记录完成内容、支持矩阵、验证结果、参数缺项和未来触发方案。

验证使用合成输入及本地原生登记，不重跑策略或研究。运行 Python/pytest 前设置 2 GB 虚拟内存上限。最终检查变更范围、文档链接及已接受回函摘要。
