**⚠️ 本文推翻该报告 §2 的归因排序**（原判"步骤(3) 平滑函数"为最强因，实测证伪）

## 0. 结论

| 原报告归因 | 实测裁定 |
|---|---|
| ① 步骤(3) 平滑函数未指定（"最强证据"） | ❌ **证伪**：四个平滑变体的成分命中率完全一样（32~33%） |
| ② 数据源（Wind 段 ρ 更高） | 保留，但降为次要 |
| ③ 口径替代 | 其中**样本空间代理**升为腿只数不对称的主因 |
| — | ⭐ **新第一因：PIT 可知日用了 CSMAR 批次日** |

腿只数不对称与得分命中率是**两个不同的病**，原报告把它们混成了一个：

- **腿只数不对称**（我方 G/V 1.032 vs 官方 0.674）→ 主因是**样本空间代理**，不是平滑函数

## 2. 步骤(3) 假设：被证伪

原文步骤(3) 只说"平滑处理，转换为 0 至 1 区间"，未给函数。测了四个候选：

| 变体 | 概率=1 候选 | 腿只数 | G/V | 成长命中 | 价值命中 |
|---|---|---|---|---|---|
| A 经验秩分位（现行） | 597 / 787 | 298 / 393 | 0.758 | **33%** | 55% |
| B logistic（与步骤(4) 同函数） | 491 / 683 | 245 / 341 | 0.718 | 32% | 45% |
| C logistic + 0.1/0.9 截断 | 503 / 689 | 251 / 344 | 0.730 | 33% | 45% |
| D 正态 CDF Φ(z) | 606 / 780 | 303 / 390 | 0.777 | 32% | **59%** |
| **官方** | — | **207 / 307** | **0.674** | — | — |

**读法**：
1. **命中率对平滑函数完全不敏感**（成长 32~33% 横贯四个变体）→ 原报告的"最强证据"不成立。
2. G/V 四个变体只差 0.06，而**换真实样本空间一步就从 1.032 走到 0.72~0.78**（离官方 0.674 只剩 0.05~0.10）
   → 不对称的主因是**样本空间代理**（`total_mv` 排名带 vs 中证2000 真实成分）。

原报告推理链的错处：由"秩分位天生对称"正确推出"腿只数会对称"，但**越过实测**直接把它
当成了 ρ 不足的主因。实测表明它连腿只数都不是主因。

## 3. 阈值无关的得分质量：价值好，成长是噪声

绕开全部选样规则，直接取 top-N（N = 官方腿只数）：

| 得分 | top-N 命中 | 随机基线 | 倍数 | 官方成员在我方得分里的分位（中位） |
|---|---|---|---|---|
| 原始**价值**得分 | **50.3%** | 15.7% | **3.2×** | 0.156 |
| 原始**成长**得分 | **12.4%** | 10.6% | **1.2×** | **0.493** |

分位 0.493 = 官方成长腿成员在我的成长得分里正好落在**中位数**，与随机洗牌无异。

单因子：

| 价值侧 | 命中 | | 成长侧 | 命中 |
|---|---|---|---|---|
| EP | 48.7% | | SalG | 17.9% |
| CFP | 41.8% | | ProG | 14.9% |
| BP | 41.4% | | **ΔROE** | **10.4%（= 随机）** |
| DP | 22.4%（退化：约半数并列） | | | |

⚠️ 反常信号：**三个成长因子合成后（12.4%）比最好的单因子 SalG（17.9%）还差**。
"因子弱"解释不了这个——合成把信息弄没了，指向构造缺陷而非因子无效。

⚠️ **本节读数的重要限定**：2026-06-15 这个截面处在 `stock_financial` 的**数据封冻期**
（见 §4.2），成长因子在此处本就无米下锅。故"成长因子是噪声"在**历史窗**上未经证实，
本节只能证明"在 2026-06 这个截面上成长得分无判别力"。真正的历史窗证据是 §4.1。

## 4. 根因

### 4.1 ⭐ PIT 可知日用了 CSMAR 批次日 → 每个调样日丢掉整整一个季度

`stock_financial` 96.5% 来自 CSMAR，其 `ann_date` 是**数据集批次日**而非首披日。
旧实现按 `ann_date <= asof` 过滤，实测（中证2000 那批股票，`income.B001100000`）：

| 报告期 | 表内行数 | `ann_date` 范围 | 该年 6 月调样日前可见 |
|---|---|---|---|
| 2018-03-31 | 1,137 | 2018-04-24 → **2021-02-03** | **3 只（0%）** |
| 2020-03-31 | 1,248 | 2020-05-09 → **2024-08-02** | 8 只（1%） |
| 2022-03-31 | 1,682 | 2022-04-29 → **2025-01-03** | 6 只（0%） |
| 2024-03-31 | 1,902 | 2024-04-27 → **2025-05-01** | 5 只（0%） |

`min(ann_date)` 都是**真实披露日**（4 月下旬），`max` 才是批次日 —— 分布双峰，
绝大多数行拿到的是批次日，而批次日可晚**两到三年**。

**后果**：每个 6 月调样日，官方用 Q1，我用上一年**年报**（滞后一整季）；12 月调样日同理。
这解释了 §3 的分裂——**成长因子是趋势/差分，命脉在最新一季；价值因子是水平，扛得住一季**。

修正后实测（抽 400 只）：

| 调样日 | 修正前最新可知 | 修正后 | 官方应用 |
|---|---|---|---|
| 2018-06-11 | 2017-12-31 | **2018-03-31** ×354 | Q1 ✓ |
| 2018-12-17 | 2018-06-30 | **2018-09-30** ×354 | Q3 ✓ |
| 2020-06-15 | 2019-12-31 | **2020-03-31** ×354 | Q1 ✓ |
| 2024-06-17 | 2023-12-31 | **2024-03-31** ×390 | Q1 ✓ |
| 2024-12-16 | 2024-06-30 | **2024-09-30** ×391 | Q3 ✓ |

### 4.2 `stock_financial` 整表停在 2025-03-31

不加任何 PIT 过滤，这批股票 `income` 的最大报告期就是 **2025-03-31**（1,938 只）。
→ 2026 年的任何 asof 都在用 **15 个月前**的财务数据。这是**独立的运维缺口**，
`_fetch_series` 的修正救不了它，须走上游补采。

### 4.3 `stock_indicator` 2015–2024 只有月末数据

每年仅 12 个交易日有行。两个后果：
- 市值带排名用**最多 17 天前**的快照（2024-12-16 调样 → 用 2024-11-29）
- `avg_mv_1y`（**EP/CFP/BP/DP 四个价值因子的公共分母**，原文"过去 1 年日均总市值"）
  实际只由 **12 个月末点**平均得到

实测代价：横截面上把分母换成当日 `total_mv` → 价值命中 50.3% → **52.6%**（+2.3pp）。
真实但二阶。**可根治**：`stock_daily_price.close` × 前向填充的 `stock_share_capital.total_shares`
可算出真正的日频总市值（代价是吃 B3 那条线已知的 SHARES 缺口）。

### 4.4 残缺快照导致整期被静默跳过

`stock_indicator` 在 2025-12-15 全天只有 **26 行**（正常约 5,200；2025-09~2026-03 整段如此）。
`sample_space` 取 `max(trade_date) <= asof` 拿到残缺日就直接用 → 返回 0 只 →
`build_pair` 里 `if not len(sp): continue` **无声吞掉整期**。
**Gate 0 正式跑因此只建了 21 期而非 22 期，全程零告警。**
这与 SalG/ProG 曾静默全空是同一类流程缺陷：**空结果必须出声**。

## 5. 修法

### 5.1 PIT：可知日 = `min(ann_date, 法定披露截止日)`

| 报告期 | 法定披露截止日 |
|---|---|
| Q1 (03-31) | 当年 04-30 |
| 半年报 (06-30) | 当年 08-31 |
| Q3 (09-30) | 当年 10-31 |
| 年报 (12-31) | **次年** 04-30 |

**为什么这不是前视**：法定截止日是真实披露日的**上界**（合规公司必在其前披露）。
用上界当可知日 → 我看到数据的时刻**不早于**真实可知时刻 → **保守**。
而 CSMAR 批次日比截止日晚数月至数年，那才是把数据无理由推后。
取 `min` 是为了让确有首披日的行（Wind 段、以及 CSMAR 里 `ann_date` 早于截止日的行）继续用自己的真实日期。

⚠️ **残余风险**：**超期披露**的公司会被当成按时披露 → 对这少数标的构成前视。
库内无披露延期字段可逐票剔除，**须写进结论限定语**，结论仍标 `provisional`。

**实现位置**：只改 `pure_style_builder._fetch_series`（SQL 粗筛改按 `end_date`，
在 pandas 里算修正可知日再过滤）。`pit_ttm_with_known` 的 `known_date` 完全由传入的
`ann_date` 列推导，**故生产 PIT 链一行未动**。

### 5.2 快照护栏

`sample_space` 改为：在过去 400 天内取**行数达到该窗口峰值一半**的最近一个交易日。
`build_pair` 跳过整期时**打印告警**并记入 `PairResult.skipped`。
验证：`sample_space(2025-12-15)` 由 0 只 → **1,575 只**。
