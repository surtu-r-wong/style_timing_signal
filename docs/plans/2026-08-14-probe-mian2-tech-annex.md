## 1. 数据源与宇宙

### 1.1 表：`stock_selector.stock_daily_price`（不是 `_qfq`）

| 项 | 实测 |
|---|---|
| 类型 / 大小 | 普通表 `relkind='r'`，**4,909 MB**，`reltuples` 16,727,401，**精确 COUNT = 18,329,890** |
| 日期跨度 | **1990-12-19 ~ 2026-08-13**（8,702 个 `trade_date`） |
| 票数 | 6,498 个 `ts_code` |
| 索引 | PK `(ts_code, trade_date)`；**`idx_price_trade_date` 单列 `trade_date`**（← 按日聚合走它，是 §2 那 11 s 的原因） |
| 相关列 | `open/high/low/close/pre_close`(numeric)、`volume`(bigint)、`amount`、`turnover`、`adj_factor`、`close_hfq/pre_close_hfq/...`、**`pct_chg`**、`change_amt`、`data_source`、`available_at`、`updated_at` |

**`stock_daily_price_qfq` 是 VIEW 不是表**（`relkind='v'`，0 bytes）。视图定义把
`open/high/low/close/pre_close` 全部乘同一个 `adj_factor/latest_adj`，并且**先对全表做
`GROUP BY ts_code max(adj_factor)`** —— 每查一次就全表聚合一次。
→ **面2 一律不碰这个视图**：`close/pre_close` 的**比值对该缩放不变**，
用原表算收益与用 qfq 视图算收益**逐位相同**，但成本差一个数量级。
（`breadth.py:79` 走的是 qfq 视图，那是它自己的历史选择，不构成面2 的先例。）

### 1.2 收益定义：**必须用 `close/pre_close − 1`，不能用 `pct_chg`**

- `pct_chg` 在近端**全为 NULL**：2026-06-30 与 2026-08-11 两天 `COUNT(pct_chg)` = **0 / 6,144** 与 **0 / 6,155**；
  而 2014/2018/2022 的抽查日 100% 非空 → 该列**中途断供**，用它会在 holdout 段整段变 NaN。
- 一致性实测（2018-06-29，3,354 行）：`max|pct_chg/100 − (close/pre_close − 1)|` = **5.04e-5**，
  超 5 bp 的行 **0 行** → 两口径在有数段等价，故切到 `close/pre_close` **无口径漂移代价**。
- `pre_close` 是**除权除息后的昨收**（Tushare 口径），即 `close/pre_close−1` 已含分红送转调整，
  **不需要**再用 `adj_factor`。

### 1.3 宇宙：两个现成定义各是什么，以及为什么两个都不能照抄

| 现成宇宙 | 出处 | 定义 | 2026-06-30 实测口径 |
|---|---|---|---|
| **breadth 宇宙** | `backtest/breadth.py:79-83` | `stock_daily_price_qfq` 的 `close IS NOT NULL`，**无任何代码过滤**；日级 `min_active=500` 剔未灌全日 | **6,144 只** |
| **thermo 宇宙** | `backtest/thermo_probe.py:126-130` `_ROW_FILTER` | `volume>0 AND pre_close>0 AND high,close NOT NULL AND ts_code LIKE '60/68/00/30%'` | **5,235 只** |

**⚠️ 两个都被港股污染（本次侦察发现，此前未见记录）**：该表自 **2025-01-02** 起灌入
**港股**（`.HK` 后缀，218,613 行，2025-01-02 ~ 2026-08-13）。2026-06-30 的后缀分布 =
`.SZ` 2,894 / `.SH` 2,311 / **`.HK` 616** / `.BJ` 323。

- **breadth 宇宙**（无过滤）自 2025-01 起把 **616 只港股**算进广度分母 —— 已提交的
  `backtest/output/breadth.csv`（末日 2026-06-30，故是污染后重建的）在 **2025-01 以后的段落含港股**。
  对面2 只影响 **holdout 报告段**（2025-2026），**不进任何闸门**（闸门窗止于 2023-12），
  但诊断列若跨全窗算就会吃到这一段 → 预登记须限定诊断窗 = 选择窗。
- **thermo 宇宙**的前缀过滤**同样漏网**：港股代码是 4 位数（`ts_code` 长度 7，如 `1681.HK`），
  其中 `00xx.HK / 30xx.HK / 60xx.HK / 68xx.HK` 会被 `LIKE '00%'` 等命中 ——
  2026-06-30 实测 **616 只港股里有 49 只被 thermo 前缀过滤放行**。

**→ 面2 的宇宙建议（零新自由度的写法）**：
用**后缀**而非前缀，即 `ts_code LIKE '%.SH' OR ts_code LIKE '%.SZ'`，
再叠 thermo 的三条行级有效性条件（`volume>0 AND pre_close>0 AND close IS NOT NULL`）。
理由三条：
1. 这不是"新宇宙"，是 **thermo 现成条件的等价修正版**——把它本来就想排除的非 A 股真的排干净
   （thermo 的 `60/68/00/30` 意图就是"沪深主板+创业+科创"，港股是它写时不存在的数据）；
2. **不引入市值/流动性/ST/次新等任何选择性条件** → 零新自由度，也就零"事后可调"的旋钮；
3. 与 breadth 宇宙的差别在**闸门窗内几乎为零**（2014-2023 段该表只有 `.SH/.SZ/.BJ`，
   而 `.BJ` 在 2014-06-30 = 0 只、2018-06-29 = 29 只、2022-06-30 = 118 只，
   是否含 `.BJ` 是 §7 的一条待拍板项，建议**不含**，理由见 D2）。

## 2. 两个候选序列的构造口径与计算成本

### 2.1 X1 = 截面收益离散度 —— **完全下推 SQL，实测 11 s**

已实测（`connect_timeout=15`、`statement_timeout=400s`、只读会话）：

```sql
SELECT trade_date, COUNT(*) AS n,
       STDDEV_SAMP(close/pre_close - 1)::float8 AS xs_sd,
       AVG(close/pre_close - 1)::float8         AS xs_mean,   -- 等权组合日收益，X2 要用
       PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY close/pre_close - 1)::float8 AS xs_med
FROM stock_selector.stock_daily_price
WHERE trade_date >= DATE '2012-01-01'
  AND (ts_code LIKE '%.SH' OR ts_code LIKE '%.SZ')
  AND close IS NOT NULL AND pre_close > 0 AND volume > 0
GROUP BY trade_date ORDER BY trade_date
```

| 项 | 实测 |
|---|---|
| 耗时 | **11.07 s** |
| 返回行数 | **3,547 行**（2012-01-04 ~ 2026-08-13）—— 议程估的 "~3,000 行序列" 属实 |
| 客户端内存 | 3,547 × 5 列 ≈ **0.2 MB**，零 OOM 风险 |
| 样值 | 2012-01-04 `n=2228, xs_sd=0.02328`；2026-08-13 `n=5200, xs_sd=0.02625` |

**为什么必须下推而不是拉面板**：`breadth.py` 的做法（`cur.fetchall()` 拉长表再 `pivot`）
在 2012 起点上是 **~11M 行 Python 元组**（`(str, date, Decimal)` 约 250 B/行）→ **≈2.8 GB 客户端峰值**，
正是 `ops-b3-preflight-oom` 那条内存史的同一形状。下推后是 3,547 行。
→ **预登记应明写"X1/X2 的原始序列一律由 SQL 聚合产出，禁止在客户端持有个股面板"**。

### 2.2 X2 = 个股平均相关性 —— 两条替代路线的调研结论

#### (i) 方差比隐含平均相关（**推荐**）

等权组合方差的分解恒等式（N 只股票、等权 1/N）：

```
σ²_p = (1/N²)·Σ_i σ²_i + (1/N²)·Σ_{i≠j} ρ_ij σ_i σ_j
```

令所有 ρ_ij 等于同一个 ρ̄（等相关近似），解出**隐含平均相关**：

```
        σ²_p − (1/N²)·Σ_i σ²_i
ρ̄  =  ───────────────────────────────
      (1/N²)·[ (Σ_i σ_i)² − Σ_i σ²_i ]
```

三个所需量全部是**按日的标量**：`N`、`Σσ_i`、`Σσ²_i`，外加 `σ_p`（等权组合收益的滚动标准差，
其日收益 = §2.1 已经算出的 `xs_mean`）。

**文献名**（预登记引用用）：
- **Solnik & Roulet (2000), "Dispersion as Cross-Sectional Correlation", *Financial Analysts Journal*
  56(1)** —— 用截面离散度反解平均相关的原始文献，也正是 §2.3 那条"X1 与 X2 近似同一物"的来源；
- **Driessen, Maenhout & Vilkov (2009), "The Price of Correlation Risk", *Journal of Finance* 64(3)**
  —— 上式的现代形式（CBOE 隐含相关指数 ICJ 的同一代数）；
- **Pollet & Wilson (2010), "Average correlation and stock market returns", *JFE* 96(3)**
  —— "平均相关预测市场收益"这一**命题本身**的出处（他们用 100 大票逐对平均，即路线 (ii)）；
- **Garcia, Mantilla-García & Martellini (2014), "A Model-Free Measure of Aggregate Idiosyncratic
  Volatility and the Prediction of Market Returns", *JFQA* 49(5)** —— **截面离散度 = 总体特质波动**
  且**能预测市场收益**，是 X1 这一族的直接先验（也是面2 值得测的最强理由）。

**成本实测**（PostgreSQL window function 下推）：

```sql
WITH r AS (SELECT ts_code, trade_date, (close/pre_close-1.0)::float8 AS ret
           FROM stock_selector.stock_daily_price WHERE trade_date >= DATE ? AND <宇宙>),
     w AS (SELECT ts_code, trade_date, ret,
                  stddev_samp(ret) OVER (PARTITION BY ts_code ORDER BY trade_date
                                         ROWS BETWEEN 59 PRECEDING AND CURRENT ROW) AS sd60,
                  count(*)        OVER (同上) AS c60
           FROM r)
SELECT trade_date, COUNT(*) FILTER (WHERE c60=60)            AS n_full,
       SUM(sd60)      FILTER (WHERE c60=60)::float8          AS sum_sd,
       SUM(sd60*sd60) FILTER (WHERE c60=60)::float8          AS sum_var,
       AVG(ret)       FILTER (WHERE c60=60)::float8          AS ew_ret_full   -- ← 建议补上
FROM w GROUP BY trade_date ORDER BY trade_date
```

| 项 | 实测 / 外推 |
|---|---|
| 起点 2020-01-01（6.5 年，约 7.7M 行）| **138.34 s**，返回 **1,602 行** |
| 外推全历史（起点 2011-01，约 13M 行）| **≈4~5 分钟**（线性外推 ×1.7）→ `statement_timeout` 建议设 **600 s** |
| 返回行数 | ~3,700 行（**不是**千万行）→ 客户端内存 **~0.2 MB** |
| 一次性 | 与 `thermometer.csv` / `breadth.csv` 同款**建一次缓存 CSV，下游复用** |

已知边界（须登记）：
- `ROWS BETWEEN 59 PRECEDING` 数的是**该票的行**不是日历日 → 停牌票的 60 行窗**跨越停牌段**
  （与 `thermo_probe` 的 `shift(1)` 跨停牌段是同一个已登记噪声）；
- `c60 = 60` 的硬约束天然剔除**次新股前 60 个交易日**与**长停牌票**，
  但也意味着**分母 N_full ≠ X1 的 N** → §7 D4 要求 `σ_p` 必须用 **同一子集**的等权收益
  （即上面补的 `ew_ret_full` 列），否则分子分母不同宇宙、ρ̄ 会出界。

#### (ii) 随机抽样 N 股逐对（**不推荐**）

- **算力上完全可行**：取 N=100，每个滚动窗 60×100 的收益矩阵 → 100×100 相关阵约 6e5 flops，
  2,434 个交易日合计 **~1.5 GFLOP**，numpy 里**秒级**；面板 100 票 × 3,300 日 = 2.6 MB。
  即便退到"全 A 5,200 票 × 3,300 日"的稠密面板也只有 **~137 MB**（float64），本机吃得下。
- **不推荐的理由不是算力，是自由度**：抽哪 N 只？按市值前 N（→ 需 `stock_share_capital` + PIT
  市值口径，把 B3 那条 PIT 风险重新拖进来）？按指数成份（→ `index_constituent` 的成份变更 PIT）？
  随机抽（→ 需要在窗内有全历史 = **幸存者偏差**，正是 B3 已踩过并修过的坑）？
  每种都是一个**必须预登记且不可事后改**的选择，而 (i) 一条都不需要。
- 若用户仍要 (ii)，最小自由度写法 = **Pollet-Wilson 原文口径**（每个窗取窗内**成交额前 100**、
  逐对 Pearson 取平均），并且**只作为 X2 的稳健性对照、不进网格**（否则网格从 32 点变 48 点）。

**结论**：两条路线都**不需要**把个股面板拉进内存 —— (i) 靠 SQL 下推，(ii) 即使拉也只有 137 MB。
**"下 SQL / 分块 / 丢 WSL2"三选一的答案是"下 SQL"**，本机足够。

### 2.3 ⚠️ 最重要的技术发现：X1 与 X2(i) **不是两个独立信息面**

对窗内已去均值的收益，逐日截面方差 `CSV_t = (1/N)Σ_i (r_it − r̄_t)²` 在窗内取时间均值满足

```
mean_W(CSV_t) ≈ (1/N)Σ_i σ²_i − σ²_p
```

代入 §2.2 的 ρ̄ 定义（并在 σ_i 同质时化简）得

```
ρ̄ ≈ 1 − mean_W(CSV_t) / avg_i σ²_i          （Solnik & Roulet 2000 的原命题）
```

即 **X2(i) ≈ 1 − 「X1 的窗内均方」/「个股平均方差」** —— X2 就是 **X1 被个股波动水平归一化后的单调反向变换**。
两族**共享同一分子**，只在"是否除以个股平均方差"上不同。

**对预登记的三条硬后果**：
1. **不得在文本里把面2 描述成"两个信息面"**——它是"同一个二阶量的两种归一化"。
   （这与 ② 的 D1/D2/D3 情况不同：那三族至少在构造上不共享分子。）
2. **必须报 `corr(X1, X2)` 作为诊断列**（与 ②(b) 要求报 corr(分歧度, 广度) 同性质），
   让"两族是否重复"第一次有数字 —— 否则面2 会重演 ② 当年"用假设代替实测"的错误，
   只是把假设从"离散度≈广度"换成"离散度≠平均相关"。
3. **多重比较的名义 32 点是保守的**（两族高度相关 → 有效变体数 < 32）。
   这方向**有利于闸门**（p 偏保守），不需要修正，但**必须写进限制段**。

## 6. 执行环境判断：**本机跑，不必上 WSL2**

四条依据：

1. **置换算力与 ② 同量级且更小**：32 点 × 1,001 行 × 一次批量 Spearman(≤487 点)，
   ② 的 48 点版向量化实测 **11 秒**（② 自由度 10）。面2 是 32 点 → 更快。
2. **内存全程 < 100 MB**：唯一的大数据在 **SQL 侧**，客户端只收 ~3,700 行 × 6 列的日度序列
   （§2）。**只要遵守"禁止在客户端持有个股面板"这条**（§2.1），就完全不碰
   `ops-b3-preflight-oom` 那条路径。
3. **IO 是唯一成本，且是一次性的**：X1 查询 **11 s** + X2 查询 **≈4~5 分钟**，
   建一次 CSV 缓存（与 `thermometer.csv` / `breadth.csv` 同款）后**下游零 IO**。
   建议 `connect_timeout=15`、`statement_timeout=600s`、先探连接（`ops-tailscale-blackhole-diagnosis`：
   拒连**不滚动重试**，停下来讲清楚）。
4. **CLAUDE.md 的"重量级丢 WSL2"针对大回测/全量重算/长跑批处理/吃内存的数据加工** ——
   面2 一条都不沾（4~5 分钟的单条只读 SQL 不是"长跑批处理"）。

**唯一需要留心的既有怪癖（与 ④ 同款，照登即可）**：关3 走 `backtest/engine.py:19 run_strategy`，
其 `pos_eff = position.shift(1)` 配 `close.pct_change()` **经济上等价于 T 收盘成交**
（Batch 12 审计定性为**文档债不是代码错**，`docs/plans/2026-08-13-exec-price-audit.md`），
且首日建仓成本落第二天（`engine.py:27-28`）。两者对面2 是**非差分偏差**，
**原样保留、不顺手修**。附带：blend carry 止于 **2026-04-29**，只影响 holdout 报告段。

## 7. 【预登记待拍板项】—— 冻结前必须钉死的全部自由度

> 每项给 1~2 个建议默认值。凡不钉死的，跑完之后都会变成事后自由度。

**D1｜宇宙定义（最重要的一条）**

AND pre_close > 0 AND volume > 0`，**不含 `.BJ`、不含 `.HK`**，**不做**市值/流动性/ST/次新任何筛选。
理由 = thermo 现成条件的等价修正版（把它本就想排除的非 A 股真排干净），零新自由度（§1.3）。
备选：加回 `.BJ`（2014 年 0 只 → 2026 年 323 只，**是一个随时间增长的成分断层**，不建议）。
**必须一并钉死**：`stock_status`（有 `is_st/is_new` 列）**不可用于本探针** ——
实测该表 2014 年只有 244 行、2019 年 2,226 行、2022 年只覆盖 159 天，**2023 前极度稀疏**，
拿它做过滤会造出一个"早期不过滤、后期过滤"的时变宇宙。

**D2｜收益口径**
→ **建议默认**：`close/pre_close − 1`（原表，非 qfq 视图）。
理由：`pct_chg` 列近端**全 NULL**（2026 抽查 0/6,144），而两口径在有数段一致到 5e-5（§1.2）；
qfq 视图对比值不变但成本高一个数量级。
**必须一并钉死**：**不做**任何异常收益剔除/缩尾。若用户要剔，须现在就定阈值——
实测 `|ret| > 30%` 的行数逐年 **19 ~ 460 行**（2017 年 437、2021 年 460，主要是**新股首日**），
默认建议是**不剔**（剔就要定"首日/前 N 日"的 N，是新自由度），
并在限制段写明"X1 含新股首日尾巴"。备选：用 `stock_meta.list_date`（覆盖 6,498/6,500，完整）
剔上市前 **20** 个交易日 —— 需**现在**拍板，跑完再加算事后调参。

**D3｜X1 的具体统计量：标准差 vs 稳健离散度 vs 是否用绝对收益**
议程原话是"截面收益离散度"，没说用哪个。
→ **建议默认**：**`STDDEV_SAMP`（ddof=1）的横截面标准差**，**用原始有符号收益**，**不去均值化处理**
（截面标准差本来就已经中心化）。理由：`level_signal` 的滚动 z 化对尺度不变，
ddof 与是否年化都**不影响任何下游数字**（② 自由度 6 已钉死同一条）。
**明确不采纳**"绝对收益的截面均值"——那是**一阶**量（≈ 市场整体波动幅度），
会与"当日市场涨跌幅"高度混同，属命题错配。
备选（稳健版）：截面 IQR 或 MAD ——**二选一，不得都测**（都测 = 网格从 32 变 64）。

**D4｜X2 的估计器 / 窗长 / 分母一致性（三件套）**
→ **建议默认**：
- 估计器 = **§2.2 (i) 的方差比隐含平均相关**（Solnik-Roulet / Driessen 代数），**不用**逐对抽样；
- 窗长 = **60 个交易日**（≈1 季度；与 `GRID_ZW` 的 60 档同频，且已实测成本）；
  备选 120 日（更稳，但把序列起点再推后 60 天，且与网格 zw 的语义重叠更多）；

**必须一并钉死**：`ROWS BETWEEN 59 PRECEDING` **跨停牌段**这一噪声**原样接受、写进限制段**
